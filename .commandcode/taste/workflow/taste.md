# workflow
- Use git workflow: work on feature branches, not main. Confidence: 0.95
- Stage and commit only: `git add <files> && git commit -m "<msg>"` (no `git add -A`). Confidence: 0.90
- Use ESP-IDF build system: `idf.py build` inside project dir. Confidence: 0.90
- Use esptool.py directly for flashing (not idf.py flash) to get verbose output and avoid port issues. Confidence: 0.85
- Use `read -r` in shell for multi-line input to preserve escapes. Confidence: 0.85
- Use `git stash push -m "<msg>"` for safe temporary stashing. Confidence: 0.85
- Prefer: working on existing code → analyze, reason, suggest, ask before changing. Confidence: 0.80
- For commits: use `git commit -F - <<'EOF'` with heredoc for multi-line messages, include Co-authored-by footer. Confidence: 0.80
- Use // region / // endregion pragma marks in C++ for code folding. Confidence: 0.80
- For ESP32 pin assignments: document in config header with SPI_ATTACH, D/C, RST, CS etc. Confidence: 0.70
