## Font Pipeline (ttf2c.py)
- **Baseline anchor**: PIL 9+ defaults to `anchor='la'` (left-ascender). All font rendering uses `anchor='ls'` so the text origin IS the typographic baseline.
- **Downsampling**: Maxpool (ANY pixel in factor×f block ON→output ON) instead of NN, preserving thin features like `,` `.` `:` that would vanish at odd hi-rez offsets with NN.
- **Baseline positioning**: Phase 2 places each glyph relative to the baseline row (not centered in cell). Baseline row is computed from typographic extents (ascent + descent). If the cell is tall enough, content is centered; if too short, descenders are preserved and ascenders clipped.
- **Proportional per-glyph advances**: Instead of fixed-width cells, `ttf2c.py` emits a `font_xxx_advances[]` array with each glyph's freetype advance width. `Display::DrawString` uses per-glyph advances so spacing matches the TTF designer's intent (uniform 1px right side bearing for norns/digi-one). `FontAdvance(Font)` returns the fixed max advance for layout estimation; `FontAdvance(Font, unsigned char c)` returns the per-glyph advance.
- **Font files**: `UI/fonts/ttf2c.py` converts TTF→C header. Fonts stored in `main/fonts/`. 3 active pixel fonts: digi_slim_3x6, digi_one_5x6, norns_6x7. `analog_one_3x5.h` is kept as reference but removed from code (identical to norns).
- **Norns extended range**: norns.ttf has 138 non-empty glyphs > 0x7F spread across codepoints up to U+ED64. `norns_ext_gen.py` generates `norns_ext_6x7.h` with sorted codepoints array + binary search lookup. Cell width = max_adv (9px). UTF-8 decoding in `DrawString` enables rendering extended icons (`←↑→↓▶●` etc.).

## Known Issues
- **TBDaits (Plaits port) — crash AND 5–10 Hz overrun crackle FIXED & hardware-verified (2026-10-29)**:
  - The crashes ("load stereo plugin, touch params, DSP reboots") were `SetChannelParamValue` dereferencing `sp[1]` = nullptr for stereo plugins on ch0 (`005cc172`).
  - The **5–10 Hz overrun crackle** (`max ≈ 950–1,000 µs` single-block spikes against the 725.6 µs budget despite `avg ≈ 268 µs`) had two interacting root causes (full analysis in `doc/tbdaits-crackle-evidence.md`):
    1. `LinkEndpoint::pushOnChange()` ran at 10 Hz (`kStreamPeriodMs = 100` ms) on Core 0 and unconditionally called `GetCStrJSONSoundProcessors()`, `GetCStrJSONGetPresets(0/1)`, `Favorites::GetAllFavorites()`, and `GetCStrJSONActivePluginParams(0/1)` to compute FNV-1a hashes — reading and RapidJSON-parsing 4 files from LittleFS/SPIFFS on SPI Flash 10 times per second and thrashing the shared SPI0/SPI1 Flash+PSRAM bus/cache. Fixed via `ctagDataModelBase::GetGeneration()` + per-model dirty-cached JSON strings (`SPManagerDataModel`, `ctagSPDataModel`, `FavoritesModel`), eliminating all steady-state SPIFFS reads and RapidJSON re-serialization.
    2. `ctagSPAllocator::AllocateInternalBuffer(114688)` missed the largest contiguous internal DRAM region on ESP32 (`3FFE4350..40000000` = `113,840 B`, TLSF bucket floor `110,592 B`) and fell back to external SPI PSRAM, placing both the 14 KB `ctagSoundProcessorTBDaits` (`plaits::Voice`) object and its 16 KB `shared_buffer` in PSRAM. Fixed by stepping `AllocateInternalBuffer` into the `110,592 B` internal SRAM1 block, sharing the mutually-exclusive `resonator_`/`string_`/`fm_voice_` arrays in `rings::Part` (`TBDings` stereo size `113,944 B → 105,708 B`), and excluding `RestServer`, `BtMidiReceiver`, `components/network`, `spiffs_image/www`, and the unused `midiuart_instance` from the BBA DSP build (137.9 KB internal DRAM still free after the 110.6 KB internal SRAM arena). Also initialized all `cv_*`/`trig_*` atomics to `-1` and wired `cv_timbre`/`cv_morph` in `ctagSoundProcessorTBDaits`.
- **C3 BLE pad-off is a handled condition — do NOT reinstate blind connect attempts (2026-10-29)**: the auto-reconnect must be the bounded 2 s half-duty advertisement probe (`BtMidiReceiver::TickReconnect`) that connects only when the pad is seen advertising. The original blind `ble_gap_connect` to the absent peer (30 s timeout, 100 % scan duty, re-armed every 3 s) starved the single core, missed the link heartbeats past the quiet threshold and crash-looped the C3 (~1.5 s resets, USB dropped off the bus) — presented as "DSP OFF", refused loads and "constant reboots". Quiet thresholds are 10 s on BOTH ends (`kOfflineAfterMs` in `main/LinkEndpoint.cpp` and `uimcu/main/LinkClient.cpp`). Boot does not blind-connect (`on_sync` only loads the peer).
- **Opening the C3 USB console resets the C3** (`rst:0x15 USB_UART_CHIP_RESET` — the Windows host driver pulses control lines on open) and, over the shared-power tie, browns out the A1S too: expect ~6–8 s of re-boot/re-handshake and a DSP OFF flicker after every console open. `uimcu/tools/screenshot.py` polls `getProxyState` until `active0` is populated (boot metadata arrived) before sending commands.
- **Debug access from the C3 bench console**: all `/debug` replies echo `"cmd"` (the C3 frame parser drops cmd-less frames), and the C3's DebugLink forwards unknown `/debug/*` to the DSP (2 s timeout, `dsp offline` when down). `uimcu/tools/screenshot.py` = framebuffer→PNG + arbitrary `/debug` commands.
- **GPIO0 = I2S MCLK, MUST NOT be used as GPIO input**: On BBA, GPIO0 is configured as I2S MCLK output by the I2S peripheral. Calling `gpio_config()` with `GPIO_MODE_INPUT` or `gpio_set_direction(GPIO_NUM_0, GPIO_MODE_INPUT)` disconnects the I2S peripheral output, killing MCLK and stopping all audio. `UserInput::Init()` and `StartSoundProcessor()` must NOT touch GPIO0. BTN2 (OK) is unavailable. Button mapping (BTN1 only, PANEL_IN state): short press = OK (BTN2_SHORT), long press = MOD mapping (BTN2_LONG), double-click = BACK. Double-click detection is in UserInput.cpp (300ms window). Single tap has 300ms delay to allow for second tap — handled by pendingShort timer in inputTask().
- **Interrupt Watchdog**: ESP32-D0WD-V3 rev3.1 + PSRAM + dual-core requires `CONFIG_ESP_INT_WDT=y`. BT coex calibration during codec I2S init can exceed the default 300ms timeout — set `CONFIG_ESP_INT_WDT_TIMEOUT_MS=5000` in `sdkconfig.defaults.a1s`.
- SD card FAT32: use `esp_vfs_fat_sdmmc_mount()` with `gpio_cd = GPIO_NUM_NC` to avoid card detect hang.
- Sound processor allocator: 112KB internal buffer may not fit in DRAM when BT is active — falls back to PSRAM via `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)`.
- **DRAM exhaustion → silent UI freeze**: After audio init, only ~22KB DRAM remains (largest free block ~17KB). `UserInput::Init()` must be called from `UIMenu::TaskFunction` (post `xTaskCreatePinnedToCore`), not from `UIMenu::Init()` — the input task's 2KB stack fragments the heap so the UIMenu task's stack can't allocate contiguously. UIMenu stack is 4096 (not 8192) since it only polls a queue + draws display. See `doc/ui-menu-architecture.md` for full root cause.
- **Elements output level overdrives codec**: The Elements DSP engine (Mutable Instruments port) outputs float values well beyond TBD's expected ±1.0 range. Elements' `SoftLimit(x) = x*(27+x²)/(27+9x²)` is NOT a hard limiter — it becomes linear (gain~1/9) for large x, allowing outputs of ±11+ from the modal resonator's 52 SVF modes summing coherently. TBD's `Codec::WriteBuffer` multiplies by 32767 and clamps to int16 range, producing hard digital clipping. The dense multi-harmonic signal creates intermodulation artifacts that sound like "8-bit reduction" + distortion. Model 1 (single K-S string) stays clean because the feedback loop gain is < 1.0, self-limiting amplitude. Fixed by applying 0.125 master gain in `ctagSoundProcessorElements.cpp:179-182` (`out[i] * 0.125f`). Root cause files: `part.cc:208-211` (SoftLimit), `codec.cpp:312-325` (float→int clamping).
- **Stale encoder events corrupt mode transitions**: Fast encoder events queued during the 300ms double-click window land ahead of the pending BTN1_SHORT. When UIMenu processes them in the old mode after the user pressed OK, the cursor moves to a different item before the mode change takes effect. Fix: `UserInput.cpp:68` suppresses encoder events while `pendingShort` is true (the 300ms window after button release). This prevents any stale events from entering the queue between the last intentional scroll and the BTN. `skipEncoders` removed entirely — not needed.
- **No RGB LED on A1S (ESP32-Audio-Kit v2.2)**: Board has no WS2812 RGB LED. Upstream's RGB LED task (`led_task`, `ledData`/`ledStatus`/`ledBlink` atomics, 4KB stack) was fully removed. `InitLedRGB()` was already deleted (commit `f0ab129a`) — the LED code was dead on BBA anyway. The GPIO23 pin is the panel-link UART RX since the P6 UI split (ex-MIDI pins; the encoder lives on the C3 — never put the A1S encoder back here). CPU overload (diff > 174150 cycles / 32 samples) is tracked via `atomic<uint32_t> cpuOverload` in `audio_task()` (`SPManager.cpp:269-270`), readable over the panel link /debug stats stream.
- **A1S mic/line sharing**: On the actual ESP32-A1S AudioKit, MIC1P is wired to RIN1 and MIC1N to LIN1. `input_source=mic` therefore uses `IN1` **single-ended** (write 0x0A=0x00, 0x0B=0x00, 0x0C=0x0C; 0x0B reads back 0x02 because bit 1 is reserved), giving two independent single-ended mics: left ADC = MIC1N, right ADC = MIC1P. MIC2P/MIC2N share LIN2/RIN2 with LINEINL/LINEINR, so MIC2 cannot be separated from line-in in firmware; `INSTEREO` (IN1 left, IN2 right) is not usable for two mics on this board. `input_source=line` uses `IN2` (0x0A=0x50).
- **Elements CPU overload (second-core offload)**: `Part::Process` runs on a core-0 helper task with one-block latency; `blow_in`/`strike_in` are snapshotted by the audio task (core 1), which applies the 0.125 master gain. Production restores **52 modes** (`Voice::resolution_` default 52, `part.set_resolution(52)` on successful helper start). V9 auto step-down ladder 52 → 32 → 24 → 16 → 12 (8-block hysteresis per mode, one-way per instance) hands the render back to single-core 12 modes if the helper cannot keep up.
  - Helper at 52 modes: ~445k–555k cycles/block (over the 174,150-cycle budget; ~225k typical, 445k–555k worst-case); helper renders silent for one block while stepping down; the ladder settles at single-core 12 modes within ~25–30 ms after boot (~40 misses during settling).
  - Single-core 12 modes: ~112 µs/block (proven clean baseline).
  - Debug fields (distinct keys from Mbeads): `elementsHelperCycles`, `elementsHelperMaxCycles`, `elementsHelperOverload`, `elementsHelperStackHighWater` (-1 after V9 retirement), `elementsHelperResolution`, `elementsHelperMisses`; override via `/debug/setElementsMode{"value":12..56}`.
  - The `components/instrumentation/` component (from dadamachines fork `feature/binary-synthdefs`) provides `PERF_MEASURE("name")` RAII macros using `esp_cpu_get_cycle_count()` with lock-free atomic accumulation and a separate logging task. Available for future profiling — add `PRIV_REQUIRES instrumentation` to the target component's CMakeLists.txt and call `PerfMonitor::EnableLogging(true, interval_ms, core, priority)` to activate.
- **Elements port open issues** (not fixed by the second-core work): pitch +5.53 semitones (MIDI-to-frequency LUTs not regenerated for 44.1 kHz), dead `strength`/`play` params (`strength` hardcoded 0.5), uninitialized `cv_*`/`trig_*` slot indices (params follow `data.cv[0]`/`data.trig[0]`), extra 0.125 master gain. Details and harness evidence: `docs/elements-port-review-findings.md`.

## Architecture Notes
- **P6 cutover DONE (2026-10-29): the BBA/A1S has NO local UI.** The ESP32-C3 panel (`uimcu/`) owns UIMenu, the menupages, input and the display; the `main/` copies of those sources are dead code — excluded from the build and never to be modified. The bullets below describe the shared UI architecture — `main/UIMenu*`, `main/menupages/`, `main/UserInput`, `main/Display` references mean those dead copies; the single live copy is `uimcu/ui/`.
- UI architecture: See doc/ui-menu-architecture.md for full details. Norns-style navigation with ROOT/PANEL_IN states. Page-owned sub-page depth via onBack(). Norns-style indicator bar (no text labels) with fade timer.
- Display framebuffer: main/Display.cpp has a 1024-byte framebuffer (`fb[1024]`) and per-page dirty tracking (`dirtyPages[8]`). Physical display is SSD1309 (driver compatible with SSD1306/SSD1309, 0xC8 COM scan). DrawPixel handles page/bit reversal. Only FONT_5X7 used in UI. DrawString/DrawVUMeter/DrawScrollbar do NOT call Flush() internally — redraw methods batch then flush once. Clear() does memset+finger only (no direct I2C). ShowFWVersion() uses framebuffer + FONT_5X7.
- Encoder driver: components/drivers/encoder.cpp uses PCNT unit 0 on GPIO23/GPIO5. Polled at 1kHz, ReadDelta() returns count per poll. PCNT glitch filter enabled (val=200, ~2.5µs) to reject mechanical bounce.
- User input: main/UserInput.cpp runs Core 0 task at idle+3. GPIO36 (BTN1) with 20ms debounce, 500ms long-press threshold. FreeRTOS queue (64 slots) dispatched via GetEvent(). EnableISR() must be called AFTER audio init. **GPIO0 is NOT used for BTN2** — it's the I2S MCLK output. Double-click detection built into inputTask(): if two short releases within 300ms, emits BTN1_DOUBLE instead of two BTN1_SHORT. Single tap has 300ms delay before BTN1_SHORT fires (to allow for second tap). UIMenu dispatch: short = OK (BTN2_SHORT), long = MOD (BTN2_LONG), double = BACK. Encoder events are suppressed during the 300ms `pendingShort` window to prevent stale events queuing ahead of the BTN.
- Parameter editing: main/menupages/UIMenuPageParams.cpp parses plugin parameter JSON via RapidJSON, renders 6-item scrollable list on OLED, dispatches value changes through SoundProcessorManager::SetChannelParamValue(). Encoder adjusts values in MODE_VALUEEDIT, OK confirms, BACK exits. **Modulation mapping**: long-press a param (or MAP in the channel menu) opens the MOD SOURCE page — ONE capability-filtered list (numeric params → CV sources, bool params → gate sources; param JSON `cv`/`trig` members are the capability flags), ordered [Learn CC] → None → MB.* → CC1-8 → MIDI. `[Learn CC]` captures the next incoming CC into a free dynamic slot and binds it to the param (MarblesEngine::StartLearn + GetLastLearnedSlot, polled via wantsTick/onTick). Bool params are gate consumers with active-low semantics (trig==1 → OFF) — see doc/modulation-system.md Gotchas.
- Plugin browser: main/menupages/UIMenuPageHome.cpp parses available processors JSON, renders 6-item scrollable plugin list, S/M type indicators. Stereo loads to ch0 directly. Mono shows Ch0/Ch1/Both submenu. BACK navigates through sub-pages. OK (BTN2_SHORT via BTN1 short press) is the primary select action.
- SD card: components/drivers/fs.cpp InitSD() initializes SDMMC slot 1 (4-bit, GPIO34 CD), mounts as LittleFS on /sd in v5.x (was FAT on older IDF). CONFIG_LITTLEFS_SDMMC_SUPPORT must be enabled for SD detection.
- UIMenu task: 4096 byte stack, runs on Core 0 at idle+3, 20ms period. Created after StartSoundProcessor() completes. UserInput::Init() called from TaskFunction (not from Init()) to avoid DRAM fragmentation before task creation. Old Favorites::ui_task is DISABLED (GPIO5 conflict with encoder).
- Panel bar: Norns-style indicator bar at y=0, persistent at ROOT on every panel (identifies the active panel; PANEL_IN hides it). 128/PANEL_COUNT px per segment. ROOT redraws compose page content + bar into ONE flush (Display::HoldFlush) — never flush a bar-less intermediate frame.
- **Modulation system = Marbles port**: See doc/modulation-system.md for full documentation. The old LFO/seq16/gate16 engine was replaced by a port of Mutable Instruments Marbles (real submodule sources compiled in `components/mutable/`). t section: 3 trig outputs (T1/T3 random gates with 7 models incl. the upstream-hidden **Markov** heuristic, T2 = master clock, internal clock with BPM entry (20–480, 1 cycle = 1 beat) + tap tempo + fine ±60 st rate, or MIDI clock via Marbles' RampExtractor). X section: 3 quantized random CVs (6 preset scales, spread/bias/steps, ASR register, bump/tilt control modes, déjà-vu loop 1–16). Y: 1 divided random CV. Outputs at trig slots 40–42 and cv slots 98–101 (all re-assignable), cv = marbles volts × 0.2. 8 MIDI-learnable CC-to-CV slots (90–97) unchanged. Persisted to /spiffs/data/mod-config.jsn (`"marbles"` object + legacy `"ccSlots"`). PANEL_MOD subpages: SP_CLOCK, SP_T, SP_X, SP_Y, SP_CC_SLOTS, SP_CC_EDIT. Not ported (hardware-only): CV scale recording, clock self-patching auto-detect, external note CV (register value is a menu param).
- **Audio task call flow** (SPManager.cpp): `MarblesEngine::Process(cv, trig)` → Codec::ReadBuffer → DC cut → noise gate → sp[0].Process(pd) → sp[1].Process(pd) (if stereo) → Codec::WriteBuffer. MarblesEngine runs first every block (~1378 Hz, generators driven with size==1 at sr=1378.125), writing T/X/Y outputs into the CV/trig buffers before sound processors read them. MIDI task feeds clock edges via `MarblesEngine::OnMidiClock()` (atomic counter drained one per block).
- **BBA is MIDI-only — no CV/Gate DAC outputs**: the board has no analog CV or gate outs, so `Control::Update()` is deliberately never called and `pd.cv`/`pd.trig` stay at the empty defaults from `SPManager.cpp`. The modulation system drives *internal* DSP parameters, not hardware jacks. The post-cutover BBA wires only the codec, the panel-link UART (GPIO18 TX / GPIO23 RX) and SD — all UI hardware and MIDI live on the C3 panel. Don't "fix" the uncalled `Control::Update()` — that is correct architecture, not a bug.
- **CV/trig slot indices are memory-safety critical**: `cv_buffer`/`trig_buffer` are stack locals of `audio_task`. Every setter routes through `ClampCVSlot()`/`ClampTrigSlot()` in `ctagSlotBounds.hpp`. `mod-config.jsn` is on SPIFFS and hand-editable, so `LoadConfig()` type-checks every member before reading it (RapidJSON asserts compile out under NDEBUG). BBA slot space is N_CVS=102 / N_TRIGS=43 (top-level CMakeLists; 98–101 = MB.X1..X3/Y, 40–42 = MB.T1..T3).

- **UI Split (P0–P3 done, branch `feat/ui-split`)**: panel UI moved to an ESP32-C3 ("uimcu") linked to the A1S over UART. `protocol/` = shared IDF-free link component (host-tested); `uimcu/` = C3 panel firmware (ported UIMenu + pages over a `DspProxy` abstraction, SPI SSD1309 display, USB-console bench channel); A1S `main/LinkEndpoint.*` owns UART1 @921600, RX on **GPIO23** (ex-MIDI pins; the dormant midiuart driver still installs UART1@31250 first and LinkEndpoint::Start deletes/reinstalls it; GPIO19's board trace corrupts RX ≥250 kBd — do NOT move RX back) and serves `/debug/*` (shared dispatcher) + `/link/*`, pushing boot metadata + 25 Hz live stream (vu/mb/sd) + on-change JSON blobs via 10 Hz hash-diff (no SPManager hooks; `/link/metering` arms the A1S peak pass while the MIX page is visible). **P3 handshake VERIFIED live at 921600 (2026-10-28)**: clean boot → automatic handshake → boot metadata populates the C3 DspProxy cache. Root cause of the original failure = the A1S board's GPIO19 input trace corrupts RX above ~250 kBd (self-loopback-proven; see `doc/ui-split-handoff.md`) — link RX moved to GPIO23. Debug helper: `/debug/setLinkBaud {"value":N}` retunes both ends at runtime. Status: **P6 cutover committed (0c032a88) and hardware-validated** (internal DRAM 209 KB free / 110.6 KB largest block, clean-boot handshake + boot metadata, MIDI end-to-end); the A1S UART0 bench task is REMOVED (DebugUI::handleCommand is the pure /debug dispatcher routed from the panel link); leftovers (CC-slot edit fix, probe trim, compile-level UI exclusion, DebugUI::Start break, SPManager dup block) closed 2026-10-29. The `main/` copies of the menu sources are dead code; `uimcu/ui/` is the single live copy. Docs: `doc/ui-split-sdd.md` (design), `doc/uimcu-bringup.md` — **read the bench wiring/measurement rules there before touching the bench**: C3 GPIO18/19 are USB pins, no GND wire between USB-powered boards, never tie 3V3 while a board is unpowered (two boards + one OLED died to these), A1S port-open resets the chip (wait ≥9 s). Hardware: C3 #1 (soldered on carrier) USB-dead (backfeed casualty); C3 #2 flashed OK; OLED panel **working** (an early "dead panel" call was wrong — DC-pin connection). RapidJSON allocator got an internal-RAM fallback (PSRAM-less targets asserted); shared component, A1S behavior unchanged.
- **C3 (Super Mini) pin map — CONSULT BEFORE ANY PIN PROPOSAL** (full table in `doc/uimcu-bringup.md`): 0=enc1 A, 1=BTN ADC ladder (ADC1_CH1), 2=OLED CS (strap-safe: display input + ROM pull-up), 3=enc1 B, 4/5=encoder E2, 6/7=OLED SPI, 8=OLED DC, 9=TRS MIDI OUT, 10=TRS MIDI IN, 18/19=USB (never wire), 20/21=link; 11–17 = embedded flash, not bonded. **2026-10-28 strap remap**: encoder E1 was on strap pins 8/9 — a detent shorted both low → invalid boot strap → no boot (blue LED on GPIO8, active-low, lit in the failing positions; pull-ups CANNOT fix a closed contact to GND). E1 moved to 0/3; OLED DC 3→8, TRS OUT 1→9 (both strap-safe: C3 outputs, high-Z + ROM pull-up at reset reads 1); BTN ADC 0→1. **Zero spare GPIOs** — any new signal means moving one. Encoder channels (C→GND, actively pull low) must never land on strap pins 2/8/9.

## Common Workflows
- **Host unit tests (no ESP-IDF, no hardware)**: `tests/host/run_tests.sh` — compiles the **real Marbles submodule sources** (`marbles/random/*`, `ramp/ramp_extractor`, `resources.cc`) with plain g++ and runs 7 marbles tests (determinism, internal clock rate, external-clock extraction, scale quantization, Markov reachability, déjà-vu looping, slot bounds) plus 4 input-source tests. Run after any change to the modulation engine or the eurorack submodule.
- **Build**: `source /home/schrab/esp/esp-idf-v5.5.4/export.sh && idf.py build`
- **DrumRack removed from the bundle** (2026-10-26): excluded from the generated factory and the compiled library via `list(FILTER ... EXCLUDE REGEX "ctagSoundProcessorDrumRack")` in `components/ctagSoundProcessor/CMakeLists.txt` (freed ~114 KB for the Marbles port's LUTs; app partition 0x380000 now has ~68 KB headroom). Sources kept in the repo; presets on SPIFFS are harmless leftovers. To re-add, remove the two FILTER lines.
- **Full flash (all partitions + storage)**: `source /home/schrab/esp/esp-idf-v5.5.4/export.sh && python -m esptool --chip esp32 -b 460800 --port /dev/ttyUSB0 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m 0x1000 build/bootloader/bootloader.bin 0x8000 build/partition_table/partition-table.bin 0xd000 build/ota_data_initial.bin 0x10000 build/ctag-tbd.bin 0x710000 build/storage.bin`
- **Flash main app only** (no storage update): `source /home/schrab/esp/esp-idf-v5.5.4/export.sh && python -m esptool --chip esp32 -b 460800 --port /dev/ttyUSB0 --before default_reset --after hard_reset write_flash --flash_mode dio --flash_size 16MB --flash_freq 80m 0x10000 build/ctag-tbd.bin`
