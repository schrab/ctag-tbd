# Memory

## Working Rules (session-learned, 2026-10-31)
- **NEVER edit files with inline python/sed scripts — use the Read/Edit/Write tools.** Script-based patching bypassed the tooling's safety checks twice in one session and landed edits in the wrong place (a write-back after a destructor). The Edit tool's exact-match requirement is the safety net.
- **Flash APP-ONLY by default — every `idf.py flash` erases the user's presets/patches/config.** The `storage` partition is created `FLASH_IN_PROJECT` (CMakeLists.txt:108), so plain `idf.py flash` rewrites it from the repo's `spiffs_image` — wiping device presets, patches, `mod-config.jsn`, `config.json` and calibration on EVERY flash. This cost the user their patched Elements session repeatedly (2026-11-14). Use `idf.py app-flash` (or the esptool `0x10000` app-only command) whenever the change is firmware-only and runs with the existing stored data — that is almost always. A full flash (storage included) only when `spiffs_image/` content intentionally changed (new factory files/config defaults), and ASK first. Applies to BOTH DSP builds (A1S root and BBA2 `build-bba2`) and any board whose presets live on SPIFFS. The raw sample-ROM region (0xB00000+) is untouched by both.
- **Incremental sync, not full-state re-push**: a single-parameter change must NEVER trigger a full-state regeneration + transmission (the full params JSON re-push per edit — up to 20 KB for a 60-byte fact — was the root of the param-change audio clicks). Use the protocol's incremental messages (`link/pushParamValue` was defined in protocol.hpp and left unimplemented for years — check protocol.hpp for designed-but-unwired messages before inventing new mechanisms).
- **After a `spiffs_push_file.py` mui push, restart the C3 panel to rebuild its cached param table** (2026-11-17): an in-place plugin reload after pushing `mui-<id>.jsn` can leave the panel's params page showing a partial list (`Where did the parameters go?`); the device file and the DSP param table are intact — a panel reboot re-parses the pushed mui and the full list reappears (TBDings: 31 leaf params before and after). Verify with `getProxyState.params0` against the mui's leaf count before assuming a push lost anything. **(2026-11-21): the panel REBOOT itself can land in the same symptom — a `params0` truncated to 5 of 25 (TBStrings bass/mid/sustain push) while the DSP side was fully correct (`getPluginParams` knew the new ids). The boot-time params re-push raced the panel's link bring-up. Recovery WITHOUT another reboot: `/debug/setActivePlugin Void` → `/debug/setActivePlugin <plugin>` — the load's full re-push burst rebuilds the table completely.**
- **The device mp almost always holds MORE patches than the repo factory file — `spiffs_push_file.py` warns, and the backup lands as `<file>.device-backup.jsn` next to the LOCAL file (2026-11-21)**: pushing `mp-TBStrings.jsn` (1 factory patch) overwrote a device file with 2 patches (user-stored `Biqe Vocizog`, activePatch=1). Recovery: convert the backup's patch list to the current schema (drop removed param ids, insert added ones with defaults) and re-push the merged file; then MOVE the `.device-backup.jsn` files out of `spiffs_image/` (the `mui-` prefix duplicate-registration rule). Live bench param edits auto-flush into the device mp within ~5 s — a patch stored from the panel IS device data, dump-and-merge before any mp push.
- **Bench console does NOT forward `/link/*` frames** (2026-11-17): `uimcu/main/DebugLink.cpp::handleCommandImpl` returns false for any command not starting `/debug/`, so a raw `{"cmd":"/link/seqSet",...}` sent from `screenshot.py` is silently dropped — no reply, no effect. Configure SEQ params through the **panel UI** with `/debug/injectEvent` (`menu_nav.py`: ROOT wheel → SEQ → enter → MAIN cursor 2 = ARP1 → enter → row 0 = Algo), reading back via `getProxyState.seqstate`. `/debug/setPluginParam` and `/debug/*` DO forward.
- **`vTaskDelay(pdMS_TO_TICKS(n))` with n < 10 is a NO-OP on this build** (`CONFIG_FREERTOS_HZ=100` → tick = 10 ms → the macro truncates to 0 → `vTaskDelay(0)` = bare yield). FOURTH instance of a silent timing bug: the sd_audio worker's "SD bus breathable" pacing never existed — tape playback hammered the card with ~1378 tiny 64-byte transactions/s, spun core 0 flat out and produced hisses/clicks (fixed 2026-11-01, user-verified: raw `vTaskDelay(1)` ticks). Elements got it right first (see its comments). STILL BROKEN, flagged not fixed: `ctagSoundProcessorMbeads.cpp:419,436` helper wait loops (bounded, but return instantly — can false-fail a healthy helper start) and `main/UIMenu.cpp:98` (dead code since P6). Use raw ticks or `pdMS_TO_TICKS(≥10)`.
- **Tape-health counters are in the 25 Hz stream**: the `sd` object carries `"u"` (playback ring underruns — a few at start are normal, growth mid-playback = tape gaps) and `"d"` (recording dropouts — clicks baked INTO self-recorded files, not a playback-path bug). Click forensics order: `u`/`d` counters → `/debug/getLoopHist` (audio-task stalls) → I2S TX DMA depth (4 descs × 32 frames = 2.9 ms; grow via `dma_frame_num`, NEVER `dma_desc_num`).

## Font Pipeline (ttf2c.py)
- **Baseline anchor**: PIL 9+ defaults to `anchor='la'` (left-ascender). All font rendering uses `anchor='ls'` so the text origin IS the typographic baseline.
- **Downsampling**: Maxpool (ANY pixel in factor×f block ON→output ON) instead of NN, preserving thin features like `,` `.` `:` that would vanish at odd hi-rez offsets with NN.
- **Baseline positioning**: Phase 2 places each glyph relative to the baseline row (not centered in cell). Baseline row is computed from typographic extents (ascent + descent). If the cell is tall enough, content is centered; if too short, descenders are preserved and ascenders clipped.
- **Proportional per-glyph advances**: Instead of fixed-width cells, `ttf2c.py` emits a `font_xxx_advances[]` array with each glyph's freetype advance width. `Display::DrawString` uses per-glyph advances so spacing matches the TTF designer's intent (uniform 1px right side bearing for norns/digi-one). `FontAdvance(Font)` returns the fixed max advance for layout estimation; `FontAdvance(Font, unsigned char c)` returns the per-glyph advance.
- **Font files**: `UI/fonts/ttf2c.py` converts TTF→C header. Fonts stored in `main/fonts/`. 3 active pixel fonts: digi_slim_3x6, digi_one_5x6, norns_6x7. `analog_one_3x5.h` is kept as reference but removed from code (identical to norns).
- **Norns extended range**: norns.ttf has 138 non-empty glyphs > 0x7F spread across codepoints up to U+ED64. `norns_ext_gen.py` generates `norns_ext_6x7.h` with sorted codepoints array + binary search lookup. Cell width = max_adv (9px). UTF-8 decoding in `DrawString` enables rendering extended icons (`←↑→↓▶●` etc.).

- Panel bar: Norns-style indicator bar at y=0, persistent at ROOT on every panel (identifies the active panel; PANEL_IN hides it). 128/PANEL_COUNT px per segment. ROOT redraws compose page content + bar into ONE flush (Display::HoldFlush) — never flush a bar-less intermediate frame.
- **Modulation system = Marbles port**: See doc/modulation-system.md for full documentation. The old LFO/seq16/gate16 engine was replaced by a port of Mutable Instruments Marbles (real submodule sources compiled in `components/mutable/`). t section: 3 trig outputs (T1/T3 random gates with 7 models incl. the upstream-hidden **Markov** heuristic, T2 = master clock; tempo model: **global BPM** (20–480, manual/tap or measured from MIDI clock, `MarblesEngine::GetBPM()` for other plugins) × **Clock Range** multiplier (0.25/1/4 — Marbles-local, never touches BPM) × fine ±60 st, persisted as `bpm`+`tFine` in mod-config.jsn with legacy `tRate` migration) or MIDI clock via Marbles' RampExtractor. X section: 3 quantized random CVs (8 preset scales: the 7 diatonic modes + pentatonic, spread/bias/steps, bump/tilt control modes, déjà-vu loop 1–16). Y: 1 divided random CV. Outputs at trig slots 40–42 and cv slots 98–101 (all re-assignable), cv = marbles volts × 0.2. 8 MIDI-learnable CC-to-CV slots (90–97) unchanged. Persisted to /spiffs/data/mod-config.jsn (`"marbles"` object + legacy `"ccSlots"`). PANEL_MOD subpages: SP_CLOCK, SP_T, SP_X, SP_Y, SP_CC_SLOTS, SP_CC_EDIT. Not ported (hardware-only): CV scale recording, clock self-patching auto-detect, X external-processing/register mode (no CV inputs on the BBA).
- **Audio task call flow** (SPManager.cpp): `MarblesEngine::Process(cv, trig)` → Codec::ReadBuffer → DC cut → noise gate → sp[0].Process(pd) → sp[1].Process(pd) (if stereo) → Codec::WriteBuffer. MarblesEngine runs first every block (~1378 Hz, generators driven with size==1 at sr=1378.125), writing T/X/Y outputs into the CV/trig buffers before sound processors read them. MIDI task feeds clock edges via `MarblesEngine::OnMidiClock()` (atomic counter drained one per block).
- **BBA is MIDI-only — no CV/Gate DAC outputs**: the board has no analog CV or gate outs, so `Control::Update()` is deliberately never called and `pd.cv`/`pd.trig` stay at the empty defaults from `SPManager.cpp`. The modulation system drives *internal* DSP parameters, not hardware jacks. The post-cutover BBA wires only the codec, the panel-link UART (GPIO18 TX / GPIO23 RX) and SD — all UI hardware and MIDI live on the C3 panel. Don't "fix" the uncalled `Control::Update()` — that is correct architecture, not a bug.
- **CV/trig slot indices are memory-safety critical**: `cv_buffer`/`trig_buffer` are stack locals of `audio_task`. Every setter routes through `ClampCVSlot()`/`ClampTrigSlot()` in `ctagSlotBounds.hpp`. `mod-config.jsn` is on SPIFFS and hand-editable, so `LoadConfig()` type-checks every member before reading it (RapidJSON asserts compile out under NDEBUG). BBA slot space is N_CVS=102 / N_TRIGS=43 (top-level CMakeLists; 98–101 = MB.X1..X3/Y, 40–42 = MB.T1..T3).

- **UI Split (P0–P3 done, branch `feat/ui-split`)**: panel UI moved to an ESP32-C3 ("uimcu") linked to the A1S over UART. `protocol/` = shared IDF-free link component (host-tested); `uimcu/` = C3 panel firmware (ported UIMenu + pages over a `DspProxy` abstraction, SPI SSD1309 display, USB-console bench channel); A1S `main/LinkEndpoint.*` owns UART1 @921600, RX on **GPIO23** (ex-MIDI pins; the dormant midiuart driver still installs UART1@31250 first and LinkEndpoint::Start deletes/reinstalls it; GPIO19's board trace corrupts RX ≥250 kBd — do NOT move RX back) and serves `/debug/*` (shared dispatcher) + `/link/*`, pushing boot metadata + 25 Hz live stream (vu/mb/sd) + on-change JSON blobs via 10 Hz hash-diff (no SPManager hooks; `/link/metering` arms the A1S peak pass while the MIX page is visible). **C3 heap ceiling (2026-10-30, hardware-proven): the no-PSRAM C3 next to NimBLE cannot malloc contiguous blocks ≥~10-15 KB — a big-enough rapidjson DOM pool chunk returns null and the assert-less memcpy store-faults (Guru Meditation, bootloop when the plugin is persisted). Params pushes are therefore CHUNKED, FLAT and HINT-FREE (≤~1.8 KB slices, group markers + leaves, `part`/`last` framing) and the C3 holds them in a STATIC `DspParamEntry` table (`DspProxy::GetParamEntry*`), handled with no DOM at all; the Params page reads the table directly (no JSON parsing on the UI task), NetRest serializes `{"params":[...]}` from it on demand. Any new link push or C3-side JSON must respect the same ceiling. **P3 handshake VERIFIED live at 921600 (2026-10-28)**: clean boot → automatic handshake → boot metadata populates the C3 DspProxy cache. Root cause of the original failure = the A1S board's GPIO19 input trace corrupts RX above ~250 kBd (self-loopback-proven; see `doc/ui-split-handoff.md`) — link RX moved to GPIO23. Debug helper: `/debug/setLinkBaud {"value":N}` retunes both ends at runtime. Status: **P6 cutover committed (0c032a88) and hardware-validated** (internal DRAM 209 KB free / 110.6 KB largest block, clean-boot handshake + boot metadata, MIDI end-to-end); the A1S UART0 bench task is REMOVED (DebugUI::handleCommand is the pure /debug dispatcher routed from the panel link); leftovers (CC-slot edit fix, probe trim, compile-level UI exclusion, DebugUI::Start break, SPManager dup block) closed 2026-10-29. - **C3 (Super Mini) pin map — CONSULT BEFORE ANY PIN PROPOSAL** (full table in `doc/uimcu-bringup.md`): 0=enc1 A, 1=BTN ADC ladder (ADC1_CH1), 2=OLED CS (strap-safe: display input + ROM pull-up), 3=enc1 B, 4/5=encoder E2, 6/7=OLED SPI, 8=OLED DC, 9=TRS MIDI OUT, 10=TRS MIDI IN, 18/19=USB (never wire), 20/21=link; 11–17 = embedded flash, not bonded. **2026-10-28 strap remap**: encoder E1 was on strap pins 8/9 — a detent shorted both low → invalid boot strap → no boot (blue LED on GPIO8, active-low, lit in the failing positions; pull-ups CANNOT fix a closed contact to GND).
